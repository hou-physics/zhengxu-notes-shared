/update-progress skill

A narrow housekeeping skill: maintains docs/progress.md — the project's living state file that records what has been analysed, what is in progress, and what blocking issues are open. The skill is deliberately scoped to three operations, never more, so that progress.md cannot drift through partial edits.

update-progress is invoked automatically at the end of every successful /analyze-galaxy run, and can also be invoked manually after a methodology change or to refresh the Next Steps checklist.

The three operations

1. Status table

A markdown table at ## Status listing each galaxy with its line, S/N, flux, reference comparison, and a status flag (done / wip / blocked). The skill either updates an existing row in place or appends a new row — never duplicates.

2. Issue Log

A reverse-chronological list under ## Issue Log. New entries land at the top with a fixed schema (symptom / root cause / fix / affected galaxies). Once the log exceeds five entries, the oldest is moved to docs/progress_archive.md, preserving the full history while keeping progress.md short enough to read.

3. Next Steps cleanup

Each bullet under ## Next Steps is checked against the just-updated Status table. If a target is now reached (e.g. "select 3–5 galaxies" once five new rows appear since the last update), the skill proposes striking the bullet — the user accepts or declines. Striking is never automatic.

Out of scope

The skill never rewrites the entire progress.md, never touches docs/paper-notes/, never modifies anything under docs/rules/, and never deletes Issue Log entries (only rotates them to archive). These constraints exist because the same file is also edited by hand between automated updates, and a full-rewrite skill would silently overwrite that work.

Inputs

All inputs are optional. Without any, the skill reads progress.md and prints a dry-run of what would change.

Field Triggers
galaxy, line, sn, flux, reference, status Status table update
issue_title, issue_symptom, issue_cause, issue_fix, issue_affected Issue Log append (with auto-rotation)
--after-rule-change Adds affected galaxies to the Recheck Queue (called from the conflict-protocol landing actions)

How it's wired in

There is no separate Python file. The skill is one markdown configuration that Claude Code reads at session start and exposes as the /update-progress slash command. Its behaviour — what to update, how to format the entries, which fields are mandatory — is captured declaratively in the skill file itself, not in code, so reviewing the skill is reviewing the entire behaviour.

This is the simplest possible "skill": no subagent, no Python helper, no external state. It works because all three operations are text-substitution patterns over a file with a stable section layout.

Related skills

  • /analyze-galaxy invokes /update-progress automatically on success.
  • The conflict protocol (docs/rules/_conflict-protocol.md) can invoke /update-progress --after-rule-change to register a Recheck Queue update.
