/analyze-galaxy skill

Given a galaxy name, /analyze-galaxy resolves the inputs (redshift, FITS paths, line, strong tracer), runs the pre-flight cube-coverage check, writes a per-galaxy step3_analyze.py config, runs the analysis, and returns a fixed-format ≤ 800 token summary. Every clean detection and non-detection in the final sample came out of this skill; the per-galaxy variation lives in the config file it emits, not in the analysis logic, which is identical across the sample.

The skill is split between a main agent and a subagent. The main agent does cheap argument resolution and the cube pre-flight (≤ 300 tokens). The subagent does the actual analysis work, which involves reading several rule files and writing the config (~8000 tokens), and returns only the short summary to the main session.

Invocation patterns

# Auto-detect everything (line, strong, FITS paths) from
# docs/target-list.md + the canonical work_dir/ symlinks
/analyze-galaxy NGC6810

# Override the HRL (multiple HRLs present in the cube)
/analyze-galaxy NGC6810 line=H30a

# Override the default strong tracer
/analyze-galaxy NGC6810 strong=HCN32

# Legacy single-cube override (NGC 3628-style, where HRL and CO
# live in the same custom-imaged cube and the canonical symlink
# convention doesn't apply)
/analyze-galaxy NGC3628 line=H30a z=0.00281 \
  fits_pbcor=master_thesis/work_dir/NGC3628/NGC3628_H30a_v1_pbcor.fits \
  fits_nonpbcor=master_thesis/work_dir/NGC3628/NGC3628_H30a_v1_nonpbcor.fits

What the main agent resolves before spawning the subagent

From the project filesystem

  • $z$ from docs/target-list.md (Tables A + B). If blank, stop with a pointer back to /alma-query.
  • HRL line name from the same row, or by globbing work_dir/{GALAXY}/{GALAXY}_H*_pbcor.fits if exactly one match.
  • Strong-tracer default by band (Band 6 → CO(2-1), Band 7 → CO(3-2), Band 3 → CO(1-0)).
  • FITS paths via the canonical symlinks {GALAXY}_{line}_{pbcor|nonpbcor}.fits and the matching CO files.
  • Per-galaxy override row from docs/rules/exceptions.md, if present.

Pre-flight cube check

For both the HRL and the strong-tracer cube, the agent opens the FITS header and verifies that the observed line frequency $\nu_\text{obs} = \nu_\text{rest} / (1 + z)$ falls inside the cube's spectral range. If either misses, the agent stops and returns a Conflict Report per docs/rules/_conflict-protocol.md instead of proceeding. This catches mis-tagged SPWs and stale symlinks before any analysis code runs.

What the subagent does

The subagent is briefed with three sections:

  1. Domain context: cube units (Jy/beam), pbcor vs. non-pbcor conventions, the mandatory rule that the spatial mask comes from a strong tracer (not the HRL itself), frequency / velocity conversions, sanity heuristics (S/N > 50 → continuum unsubtracted; flux > 10× published → systematic error).
  2. Task: write the per-galaxy step3_analyze.py config that instantiates AnalysisConfig (signal region, noise region, velocity windows, mask-component mode) and runs analyze().
  3. Hard rules: never self-mask the HRL; never modify _step3/; always include audit comments above each SkyRegion call explaining the geometric choice; return verbatim on conflict.

The subagent does not decide rule conflicts. Any contradiction between the data and a rule (strong tracer missing, beam mismatch beyond the template, anomalously high S/N) produces a Conflict Report that lands on the main session for the user to resolve.

Return format (≤ 800 tokens)

On success:

Galaxy: {GALAXY}  Line: {LINE}
S/N: <value>  Flux: <value> Jy·km/s  Width: <value> km/s  Nbeam: <value>
vs Reference: <name> <value> (<pct_diff>%) [✅/⚠️ or N/A if first]
Script: master_thesis/my_code/{galaxy_lower}_analyse_code/step3_analyze.py
Results: results/{GALAXY}/ (summary.md, plots/, tables/)
Sanity check: <one sentence>

On conflict: the verbatim conflict block from docs/rules/_conflict-protocol.md, requiring an explicit user decision (a / b / c) before any further action.

Token economy

Stage Tokens
Main-agent argument resolution + pre-flight ~300
Subagent execution (rule files + reasoning + config writing) ~8000
Subagent → main return summary ≤ 800
Net main session cost per galaxy ~1100

Without the skill, the same workflow would consume ~9000 tokens per galaxy in the main session. The split lets the main session sustain 30–40 galaxy analyses per chat before hitting context limits.

Why a skill rather than a script

A standalone Python script could do most of the orchestration. The skill form adds three things that mattered in practice:

  1. Pre-flight termination: a Python script that finds the strong tracer missing would proceed to crash, write a half-result, or silently fall back to self-masking. The skill agent stops cleanly with a Conflict Report.
  2. Audit comments: the agent is instructed to write a short rationale above each SkyRegion call, citing NED centre / CO moment-0 peak / specific geometric considerations. This rationale then surfaces in the auto-generated summary.md and supports later debugging.
  3. Hooks: success automatically invokes /update-progress to refresh the Status table without further user prompts.
