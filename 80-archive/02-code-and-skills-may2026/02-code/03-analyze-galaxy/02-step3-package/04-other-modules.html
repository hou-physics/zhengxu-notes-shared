Other modules (referenced, not embedded)

The full _step3/ Python package contains additional modules that the three central files analyze.py, config.py, and mask.py import. They are smaller, narrower in scope, and largely self-explanatory from their docstrings — listed here for completeness rather than embedded verbatim.

Production modules

These are imported into the live pipeline and run for every galaxy in the final sample.

Module Role What it provides
cube_io.py FITS cube I/O Memory-mapped loading of HRL, CO, and PB cubes; WCS parsing; beam-area arithmetic; the streaming PB-cutoff masker that writes the per-cutoff scratch cubes used by the pipeline
flux.py Flux + S/N Moment-0 collapse, in-mask spectrum extraction, line-free noise estimation, baseline subtraction (degree from AnalysisConfig.baseline_degree), final S/N calculation
baseline_diag.py Baseline residual diagnostic Per-pixel baseline-residual measurement along the dilation-CoG mask sequence. Implements the residual subtraction shipped 2026-05-17. Used both for diagnostic plots and for the production residual subtraction along the integration sequence
geometry.py Sky → pixel geometry Conversion between sky coordinates (SkyRegion) and pixel boxes in cube WCS frames; used by analyze.py to translate the hand-picked signal/noise regions onto the reprojected grid
known_lines.py Line frequency catalogue Rest-frequency table for H$n\alpha$ ($n \in \{27\text{–}32, 39\text{–}42\}$), CO(2-1), CS(2-1), HCN transitions, plus the match_line_in_cube() helper used to identify which configured line falls in each SPW (called by step-1_download.py)
plots.py Diagnostic figures Four-panel moment-0 / mask / spectrum / scan-heatmap figures emitted at the end of every analyze() run; consumes AnalysisResult and writes into output_dir/plots/
plot_style.py Publication style Centralised matplotlib rcParams and CMasher colormap picks; called once at the top of plots.py. Keeps every figure consistent with the thesis style

Diagnostic runner wrappers

Thin scripts that produce baseline-diagnostic plots over the validation sample without re-running the full analyze() loop. Useful when inspecting residual structure across multiple galaxies at once.

  • baseline_diag_runner.py
  • baseline_diag_run_v1.py (the production v1 invoker)
  • replot.py (regenerates plots from the per-galaxy *_plot_cache.pkl)

Experimental / proof-of-concept

Modules retained as a record of explored alternatives. None of them are in the production code path; they are kept for reproducibility of the design decisions documented in the methodology.

  • CoG (curve-of-growth) variants: cog_clean_detection_poc.py, sthresh_high_res_cog.py, ellipse_cog_poc.py, ellipse_cog_spatial_null.py, ellipse_cog_with_baseline_subtraction.py, ellipse_cog_nondetection_validation.py — explored elliptical-aperture curve-of-growth flux extraction; superseded by the scan + mask-integration approach in production.
  • Auto-region exploration: auto_regions_poc.py, audit_auto_vs_manual.py, viz_auto_vs_manual.py — automated signal/noise box selection. Available behind AnalysisConfig.signal_region_mode = "dilated_footprint" / noise_region_mode = "auto", kept off by default for the final sample so the published box-mode results stay unchanged.
  • Null-test variants: nondet_spatial_null.py, matched_null_test.py, circinus_spatial_null_scale3.py — earlier null-test methodologies (see Methodology §X.4 in the thesis draft for the supersession history).
  • Baseline-residual POC: baseline_residual_poc.py — the prototype that shipped as production baseline_diag.py.
  • Per-galaxy validation overlays: ngc4945_sf1_test.py, he2-10_co_hrl_overlay.py, ngc5253_x1a_co_hrl_overlay.py, ngc7793_full_fov.py, ngc7793_mom0_overlay.py — one-off cross-check overlays generated during methodology development; not generic.
  • Didactic: didactic_clean_shortspacing.py — pedagogical demonstration of CLEAN with short-spacing recovery.

How to access the source

The full package source lives in the private project repository at master_thesis/my_code/_step3/. The three central files reproduced verbatim on the preceding pages are what the methodology text refers to; the modules listed on this page can be requested or inspected on demand.
